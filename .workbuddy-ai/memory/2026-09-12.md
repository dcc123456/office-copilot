## 启动 office-copilot 全量应用（pnpm monorepo）

用户要求「启动这个项目」，选择「全部应用并行」。仓库有 4 个 app：cli / desktop / server / task-pane。

### 环境坑（重要，下次直接用）

1. **pnpm 不在 PATH**。可用版本：`/Users/dcc/.nvm/versions/node/v24.19.0/bin/pnpm`（11.7.0，与 packageManager 字段一致）。
   统一用 node 24.19.0 + pnpm 11.7.0，保证 native 模块 ABI 一致。
2. **pnpm 的全局 store 被 broker shim 拦截**（`~/Library/pnpm/store` 的 unlink/symlink 被拒，报 `[CODEBUDDY_BROKER_DENY] EEXIST`），
   连 `pnpm -r exec` 都会因 `verify-deps-before-run` 自动跑 `pnpm install` 而失败。
   **解法：所有 pnpm 命令加 `--config.verify-deps-before-run=false`。**
3. **`better-sqlite3` 没有编译产物**（`build/Release/better_sqlite3.node` 缺失，pnpm 跳过了 build script）。
   已用 node-gyp 手工编译（针对 node 24 / ABI 137）：
   `cd node_modules/.pnpm/better-sqlite3@11.10.0/node_modules/better-sqlite3 && node <npm>/node_modules/node-gyp/bin/node-gyp.js rebuild --release`
4. **根 `pnpm dev` 是坏的**：`apps/cli` 的 dev 脚本是 `tsx src/index.ts`，无参数时打印 help 后 **exit 1**，
   pnpm 递归运行遇首个失败即中止，导致 server / task-pane 根本没起来。
   **解法：加 `--no-bail`**（建议上游把根脚本改成 `pnpm -r --parallel --no-bail --filter='./apps/*' run dev`）。
5. **端口 5173 被另一个项目占用**（`/Users/dcc/project/gits/canva-pdf` 的 vite dev server，非本仓库）。
   task-pane 的 vite 配置 `strictPort: true`，因此失败。已临时改用 **5175** 启动。
   ⚠️ 不要 kill 非本仓库的进程。
6. 本机环境注入了 `NODE_OPTIONS=--require=.../node-language-shim.cjs`，Electron 会打 NODE_OPTIONS 警告（无害）。
7. 本机有 `https_proxy`，curl 访问本地 https 需加 `--noproxy '*'`；系统 curl 是 LibreSSL，对某些 TLS 会报 protocol version，用 node fetch 交叉验证更可靠。

### 🐞 发现的真 bug：`oc replace` 不支持跨 run 匹配

**现象**：`oc list` 明明显示第 31 段是「精通高德地图api、echarts图表，，实现数据可视化」，但
`oc replace -f "，，" -r "，"` 报 `⚠ 未找到：，，`。

**原因**：该段落被 Word 切成 5 个 `<w:r>`：
```
run1 "3. "  run2 "可视化与地图技术"(粗体)  run3 "：精通高德地图api、echarts图表"
run4 "，"   run5 "，实现数据可视化和地图相关复杂功能。"
```
目标文本 `，，` 横跨 run4/run5，而 CLI 的 replace 是**逐 run 内匹配**，所以跨 run 必然失配。

**验证**：单 run 替换（`精通高德地图api`→`精通高德地图API`）✅ 成功；跨 2 个 run（`，，`）❌ 失败；跨 3 个 run（`echarts图表，，实现数据可视化`）❌ 失败。

**影响**：Word 按格式差异切 run 极其常见（加粗、字体、语言标注都会切），所以「用户肉眼看得见的连续文字」经常搜不到。README 的「已知边界」只提了 regex 不支持，**没提跨 run 这个坑**，值得补。

**修法建议**：匹配前先把段落内所有 run 的文本拼成一段做查找，命中后按偏移量回填（必要时拆/并 run，格式取首个 run 的 rPr）。
